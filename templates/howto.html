Configuring Providers

Providers are the connections to LLMs. You must configure at least one before launching runs.

OllamaLocal

Models running on your machine. Only needs the URL (http://localhost:11434). No API key required.

OpenAIAPI

GPT-4, GPT-3.5 and any OpenAI-compatible endpoint. Requires an API key.

AnthropicAPI

Claude 3/4 family. Requires an Anthropic API key.

GeminiAPI

Google Gemini models. Requires a Google AI API key.

GroqAPI

Ultra-fast inference via Groq cloud. Requires a Groq API key.

vLLMLocal / Remote

Your own vLLM server. Enter the server's base URL. Optional API key.

Add a provider
  1. Go to Providers → Add Provider.
  2. Select the type, enter a name, base URL, and API key if required.
  3. Click Test Connection — the platform queries the provider and lists available models.
  4. Save. The provider now appears as an option when creating runs.
Launching Runs

A Run is the execution of a benchmark against an LLM. Each question is sent to the model and the answer is automatically evaluated.

Basic steps
  1. Go to Runs → New Run.
  2. Select the benchmark you want to evaluate (must be loaded first).
  3. Choose the provider and model.
  4. Optionally adjust temperature, max tokens, and system prompt.
  5. Click Start Run. Progress updates in real time — the page auto-refreshes when done.
To load a benchmark that isn't loaded yet, go to Benchmarks → All Benchmarks and click Load next to it.
Advanced Run Options

The run creation form exposes several advanced settings to fine-tune how the model is evaluated.

OptionDescription
Temperature Controls randomness (0 = deterministic, 1 = creative). Use low values for reproducible evals.
Max tokens Maximum tokens in the model's response. Keep low for multiple-choice, higher for open-ended.
System prompt Global instruction prepended to every question. Select from the Prompt Library or write a custom one inline.
Few-shot examples Number of solved examples prepended to each question to guide the model (in-context learning).
Chain-of-Thought Appends "Let's think step by step" to each question, encouraging the model to reason before answering.
Parallel workers Number of concurrent requests. Higher values speed up the run but may hit rate limits.
Webhook URL A URL called via POST when the run completes. Useful for CI/CD pipelines or alerting.
Tags Comma-separated labels to organize and filter runs later (e.g. baseline, v2).
Notes Free-text field for experiment notes, hypotheses, or change descriptions.
Save your favourite configuration as a Run Template to reuse it without filling the form again.
Prompt Library

Store reusable system prompts that can be selected when creating runs — no need to retype the same instruction every time.

Create a prompt
  1. Go to Benchmarks → Prompt Library.
  2. Click New Prompt and enter a name and system text.
  3. When creating a run, pick the prompt from the System Prompt dropdown — it auto-fills the field.
Combine the Prompt Library with A/B testing or Parameter Sweep to measure the effect of different instructions on the same model.
A/B Testing

Statistically compare two runs to determine whether the performance difference is significant or just noise.

How to use it
  1. Execute two runs on the same benchmark (different model, temperature, or prompt).
  2. Go to Runs → A/B Testing.
  3. Select the two runs and click Run A/B Test.
  4. Results show the score difference, p-value (McNemar test), and whether the difference is statistically significant.
A p-value < 0.05 means the difference is unlikely to be random. The results also highlight individual questions where the two runs disagree.
Compare Runs

Compare up to 4 completed runs side by side — scores, subject breakdowns, and question-level disagreements.

Steps
  1. Go to Runs → Compare Runs.
  2. Select 2–4 completed runs from the same benchmark.
  3. Click Compare.
What you see
  • Score table — accuracy per run, colour-coded for quick reading.
  • Subject breakdown — bar chart and table showing accuracy per subject or category.
  • Disagreements — questions where runs give different answers, helping you spot where models diverge.
Unlike A/B Testing, Compare Runs is visual and multi-run — ideal for exploratory analysis rather than statistical hypothesis testing.
Bulk Run

Test the same benchmark against multiple models in a single operation — all runs are created and started automatically.

How to use it
  1. Go to Runs → Bulk Run.
  2. Select one or more benchmarks.
  3. Select one or more models (from any configured provider).
  4. Set shared parameters (temperature, max tokens, prompt).
  5. Click Launch All. All runs are tagged with a shared bulk_<ID> tag for easy filtering.
After the bulk run completes, use Compare Runs or the Leaderboard to see results side by side.
Parameter Sweep

Perform a grid search over model hyperparameters or prompts to find the optimal configuration automatically.

Sweep modes
Temperature sweep

Define a range (e.g. 0.0 → 1.0, step 0.2). One run is created per temperature value.

Prompt sweep

Select multiple prompts from the library. One run is created per prompt.

Steps
  1. Go to Runs → Parameter Sweep.
  2. Choose the benchmark, provider, and base model.
  3. Select the sweep mode and configure the range or prompts.
  4. All runs are created tagged with a shared sweep_<ID> tag.
Mind the cost: N temperature values × M token values = N×M runs. Use Cost Estimator first.
Run Templates

Save a complete run configuration — benchmark, model, temperature, prompt, few-shot count, etc. — so you can reuse it with one click.

Save a template
  1. When creating a run, fill in the desired configuration.
  2. Click Save as Template before submitting, give it a name.
  3. The template is saved and listed under Runs → Run Templates.
Use a template
  1. Go to Runs → Run Templates.
  2. Click Use Template next to the one you want.
  3. The New Run form opens pre-filled. Adjust anything you need and click Start Run.
Scheduled Runs

Schedule runs to execute automatically at a specific time or on a recurring basis — ideal for regression testing after model updates.

Create a scheduled run
  1. Go to Runs → Scheduled Runs → New.
  2. Select the benchmark, provider, model, and run parameters.
  3. Set the schedule — a one-off date/time or a recurring interval (cron expression).
  4. The system launches the run automatically at the scheduled time.
Manage scheduled runs

From Scheduled Runs you can enable/disable individual schedules without deleting them, or delete ones you no longer need.

Combine with Model History to automatically track performance drift over time.
Retry Failed Questions

If some questions in a run errored (network timeout, rate limit, etc.), you can retry only those questions without re-running the entire benchmark.

Steps
  1. Open the Run Detail page of the affected run.
  2. Click Retry Failed. A new run is created containing only the questions that errored or were skipped.
  3. The new run uses the same configuration (model, temperature, prompt) as the original.
The retry run is a separate run — you can compare it against the original using Compare Runs.
Export Results

Download run results or benchmark questions for external analysis in Excel or CSV format.

Run results → Excel

3-sheet workbook: Summary (metadata & score), By Subject (accuracy per category), Results (every question with model answer).

Run results → CSV

Flat CSV with one row per question: ID, question, model answer, correct answer, is_correct, tokens, latency.

Benchmark questions → Excel / CSV

Export all questions from a benchmark. Useful for manual review or to seed another tool.

API export

All run and benchmark data is also accessible via the REST API for programmatic export.

Both Export CSV and Export Excel buttons appear on the Run Detail page and the Benchmark Detail page.

Cost Estimator

Estimate the token cost of a run before launching it — especially useful before bulk runs or parameter sweeps.

Steps
  1. Go to Runs → Estimate Cost.
  2. Select the model and enter the number of questions.
  3. The estimator shows projected input tokens, output tokens, and total cost in real time.
Estimates are based on average question length for the selected benchmark. Actual costs may vary depending on model verbosity and system prompt length.
Leaderboard

The Leaderboard ranks models by their best score on each benchmark, using Wilson score confidence intervals for robust ranking even with small sample sizes.

Features
  • Filter by benchmark — focus on a specific benchmark to compare models head-to-head.
  • Wilson confidence intervals — lower bound is used for ranking so models with few questions aren't over-promoted.
  • Score history — see how each model has improved across successive runs.
Only completed runs appear on the leaderboard. Each model is represented by its single best run per benchmark.
Hardness Tracker

The Hardness Tracker analyses every question across all runs to classify questions by difficulty.

CategoryCriteria
EasyMost models answer correctly (>75% success rate)
ControversialSome models get it right, others wrong (25–75% success rate)
HardMost models fail (<25% success rate)
Use the hardness data to build targeted benchmarks focusing on the most discriminating questions — those where models actually disagree.
Model History

Track how a specific model's performance evolves over time across benchmarks — useful for detecting regressions or improvements after fine-tuning.

Steps
  1. Go to Runs → Model History.
  2. Select the model you want to track.
  3. The page shows a timeline of all runs for that model with scores plotted over time per benchmark.
Combine with Scheduled Runs to automatically capture snapshots at regular intervals.
Benchmark Suites

A Suite groups several benchmarks into a single named collection. Running a suite evaluates the model on all included benchmarks and produces an aggregate score.

Create and run a suite
  1. Go to Benchmarks → Benchmark Suites.
  2. Click Create Suite, give it a name, and add the desired benchmarks.
  3. From the suite detail page, click Run Suite — select the model and execution mode (sequential or parallel).
  4. Suite results show the score per benchmark and the global weighted average.
Suites are ideal for holistic evaluations — e.g. group all reasoning benchmarks together and compare models on the combined result.
Custom Benchmarks

Create your own benchmark by uploading questions in CSV format. Download the example CSV template to get started quickly.

CSV format
ColumnRequiredDescription
questionYesQuestion text
correct_answerYesExpected correct answer
choice_a … choice_dNoMultiple choice options (A–D)
subject / categoryNoTopic group for per-subject analysis
difficultyNoeasy / medium / hard
  1. Go to Benchmarks → Custom Benchmark.
  2. Download the Example CSV if needed.
  3. Upload your CSV, set a name, description, and category.
  4. The benchmark is immediately available for runs — no loading step needed.
You can also import manual answers for a custom benchmark via Import CSV Results — useful when you have pre-computed model outputs.
Import from HuggingFace Hub

Import any compatible dataset directly from HuggingFace Hub without downloading anything manually.

Steps
  1. Go to Benchmarks → Import from HuggingFace.
  2. Enter the dataset ID (e.g. cais/mmlu, openai/gsm8k).
  3. Specify the split (test, validation, train) and sample limit.
  4. Map the dataset columns to the platform fields: question column, answer column, optionally subject column.
  5. Click Import. Questions are downloaded and the benchmark is created automatically.
Requires internet access. Large datasets (e.g. MMLU with all subjects) may take a few minutes to download.
RAG Benchmark

Evaluate Retrieval-Augmented Generation: each question is accompanied by a context passage that the model can use to answer — simulating real-world document QA.

CSV format
ColumnRequiredDescription
contextYesText passage the model receives as context
questionYesQuestion about the context
correct_answerYesExpected answer (pipe-separated aliases accepted)
subjectNoTopic for per-subject analysis
  1. Go to Benchmarks → RAG Benchmark.
  2. Download the RAG Example CSV to see the expected format.
  3. Upload your CSV with context, question, and correct answer columns.
  4. The platform injects the context before each question when running the model.
The correct_answer column supports pipe-separated aliases (e.g. Paris|paris|PARIS) so fuzzy matching handles minor formatting differences.
Import CSV Results

If you already have model answers in a CSV (generated externally or offline), import them directly to create a run without re-running the model.

Results CSV format
ColumnRequiredDescription
question_idYesInternal question ID (visible in the benchmark Questions page)
answerYesModel's answer text
is_correctNotrue / false — recalculated automatically if omitted
  1. Go to Runs → Import CSV.
  2. Select the benchmark the questions belong to.
  3. Upload the CSV and confirm. A new run is created with the imported results.
REST API

All platform data is accessible via a JSON REST API at /api/v1/. Useful for CI/CD integration, scripting, or building custom dashboards.

Key endpoints
EndpointMethodDescription
/api/v1/benchmarks/GETList benchmarks (filter: loaded, category)
/api/v1/benchmarks/<slug>/questions/GETPaginated questions for a benchmark
/api/v1/runs/GETList runs (filter: status, benchmark, model, tag)
/api/v1/runs/POSTCreate & start a new run (JSON body)
/api/v1/runs/<id>/status/GETLightweight polling: status, score, progress
/api/v1/runs/<id>/results/GETPaginated per-question results
/api/v1/runs/<id>/cancel/POSTCancel a running or pending run
/api/v1/providers/GETList configured providers
/api/v1/leaderboard/GETBest score per model per benchmark

Full documentation with request/response examples is available at API → Documentation.
